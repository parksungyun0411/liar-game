# Liar Game: Java 소켓 멀티플레이어

> 최대 8명이 동시에 접속하는 TCP 소켓 기반 멀티플레이어 라이어 게임이다.
> 한 명(라이어)만 제시어를 모른 채 시작하고, 대화로 라이어를 찾아내면 시민이 이긴다. 지목된 라이어가 제시어를 맞히면 라이어가 이긴다.

![라이어 게임 타이틀 화면](./mainimage진진진짜.png)

## 핵심 요약

- **기간**: 2024.03 ~ 2024.05 (3-1 네트워크 프로그래밍 수업 팀 프로젝트)
- **팀**: 3인 (김호정 · 양승원 · 박성윤)
- **본인(박성윤) 담당**: 서버 측 멀티스레드 처리와 게임 로직(`LiarServer.java`, `OneClientModul`, `GameManager.java`), 클라이언트 UI 조정, 한글 인코딩 정리, Gradle 빌드 설정
- **기술**: Java, Swing, `Socket` / `ServerSocket`, `Thread` / `Vector`, Gradle

## 게임 흐름

1. 서버 관리자가 포트를 지정해 서버를 열고, 플레이어가 닉네임·IP·포트로 입장한다. 최대 8명이고 닉네임 중복은 막는다.
2. 게임을 시작하면 주제 풀(`주제.txt`, 177개)에서 제시어를 무작위로 고르고 플레이어 1명을 라이어로 정한다. 라이어에게는 제시어 대신 라이어라는 표시만 보낸다.
3. 무작위 순서로 1인당 10초씩 제시어를 한마디로 설명한다. 본인 차례에만 채팅 잠금이 풀린다.
4. 20초 동안 투표하고 최다 득표자를 라이어로 지목한다. 전원이 투표하면 일찍 마감한다.
5. 지목이 맞으면 라이어가 10초 안에 제시어를 추리한다. 맞히면 라이어 승, 틀리면 시민 승이다. 지목이 틀리면 라이어 승이다.

## 아키텍처

```
            LoginUi.main() (단일 진입점)
           ┌──────┴──────┐
   "서버 생성하기"       "서버 입장하기"
           │                  │
      ServerUi (Swing)   ClientUi (Swing)
           │                  │
      LiarServer          Client (Runnable, 수신 스레드)
      ├ serverThread:         │
      │  accept 루프          │ TCP (DataInput/OutputStream,
      │  접속마다             │      writeUTF 텍스트 프로토콜)
      │  OneClientModul ──────┘
      │  스레드 생성 (최대 8)
      └ gameThread: 시작 버튼을 누르면 GameManager 구동
```

- **`LiarServer`**: `ServerSocket` accept 루프를 `serverThread`로 돌리고, 접속마다 `OneClientModul` 스레드를 만들어 `Vector`에 보관한다. 게임을 시작하면 별도 `gameThread`에서 `GameManager`를 구동해 accept 루프와 게임 진행이 서로 블로킹되지 않게 한다. 인원 상한(8명), 게임 중 입장 차단, 강퇴도 여기서 처리한다.
- **`OneClientModul`**: 클라이언트 1명당 1 스레드로 수신을 기다린다. 입장할 때 중복 닉네임, 한글·영문·숫자 1~10자가 아닌 닉네임, `gm`으로 시작하는 닉네임을 거부한다. 클라이언트가 보낸 메시지를 접두사로 분기하고(`liarTopic` = 라이어의 제시어 추리, `cVote` = 투표, `chat` = 채팅), 채팅은 서버가 보낸 사람의 닉네임을 붙여 전체에 브로드캐스트한다. 전원이 투표하면 `gameThread.interrupt()`로 대기를 일찍 끝낸다.
- **`GameManager`**: 주제를 읽고, 라이어를 무작위로 정하고, 라이어 표시와 제시어를 해당 플레이어에게만 보낸다. 발언 순서를 섞어 채팅을 잠그고 풀며, 투표를 집계하고(`Collections.frequency`) 승패를 판정한다. 진행 상황은 서버가 보내는 `gm` 접두사 명령으로 클라이언트 UI(투표 다이얼로그, 결과 화면)를 원격 제어한다.
- **`ClientUi` / `ServerUi` / `LoginUi` / `VoteDialog` / `Result`**: Swing GUI다. 커스텀 `RoundedButton`과 `ImagePanel`(배경 이미지 패널)을 쓴다.

## 실행 방법

JDK 17이 필요하다. 포함된 Gradle 8.4 wrapper는 JDK 21 이상을 지원하지 않는다. GitHub Actions도 JDK 17로 `./gradlew build`를 실행한다.
리소스(이미지, `주제.txt`)를 작업 디렉터리에서 읽으므로 **반드시 리포 루트에서 실행**해야 한다.

```bash
# 빌드 (`주제.txt`를 UTF-8로 177개 읽는지 확인하는 테스트 포함)
./gradlew build

# 실행 (macOS/Linux 기준. Windows는 클래스패스 구분자를 ; 로 바꾼다)
java -cp "build/classes/java/main:." LoginUi
```

- 실행 후 한 명이 "서버 생성하기"로 서버를 열고, 나머지는 "서버 입장하기"로 접속한다.
- 채팅 화면 상단 패널의 배경 이미지(`pBack.png`)는 리포에 남아 있지 않아 비어 보일 수 있다.

## 팀 구성 · 역할

김호정 · 양승원 · 박성윤 3인 팀 프로젝트다.
원본 저장소는 [@kimhoojung/Network_11](https://github.com/kimhoojung/Network_11) (final 브랜치)이고, 이 리포는 포트폴리오 목적으로 복제했다. 개별 커밋 작성자 정보는 그대로 보존되어 있다.
다만 원본의 최종 소스는 팀원 한 명이 한 번의 커밋(`ef3f7ab`)으로 올렸기 때문에, 커밋 작성자 정보로는 실제 분담이 드러나지 않는다.

**본인(박성윤) 담당**:

- `LiarServer.java`: accept 루프 스레드, 접속 인원 상한과 게임 중 입장 차단, 게임 스레드 분리, 강퇴
- `OneClientModul`: 클라이언트 1명당 1 스레드 수신, 접두사 기반 메시지 분기, 입퇴장 처리와 브로드캐스트, 닉네임 중복 검사
- `GameManager.java`: 주제 풀 로딩, 라이어 선정, 발언 순서와 채팅 잠금 제어, 투표 집계, 승패 판정
- 커밋 `f280599`: 클라이언트 UI 조정(로그인 화면의 버튼 배치·창 크기·색, 채팅·결과 화면 이미지 교체), Java 소스의 한글 인코딩을 EUC-KR에서 UTF-8로 변환, Gradle 빌드 설정 추가

그 밖의 클라이언트 구현과 Swing UI·리소스 제작은 팀원들과 나눠 맡았다.

## 2026년 수정

포트폴리오로 다시 읽으며 아래를 고쳤다. 2024년 수업 제출 이후의 변경이다.

- `주제.txt`를 EUC-KR에서 UTF-8로 바꾸고 코드에서 문자셋을 명시해 읽게 했다. 중복 제시어 4개를 지워 177개로 정리했다.
- 게임을 시작할 때 라이어 표시와 제시어를 모든 클라이언트에 보내던 것을, 라이어에게는 라이어 표시만, 나머지에게는 제시어만 보내게 바꿨다.
- 인원 초과 응답 문자열이 서버와 클라이언트에서 달라 클라이언트가 멈추던 문제와, 중복 닉네임으로 거부된 연결이 접속 목록에 들어가던 문제를 고쳤다.
- 서버가 클라이언트가 보낸 채팅 문자열(닉네임 포함)을 그대로 전달하고, `cVote`·`liarTopic`으로 시작하는 채팅 입력을 투표·추리로 처리하던 것을 고쳤다. 클라이언트는 채팅에 `chat` 접두사를 붙여 보내고, 서버가 보낸 사람의 닉네임을 붙여 전달한다.
- 닉네임이 클라이언트의 문자열 해석에 그대로 들어가던 문제를 고쳤다. `gm`으로 시작하는 닉네임은 게임 명령으로 읽혔고, 짝이 맞지 않는 괄호처럼 정규식으로 해석할 수 없는 문자가 든 닉네임은 자기 채팅을 받을 때 수신 스레드를 죽였고, 다른 사람의 닉네임 뒤에 "님이 강퇴"를 붙인 닉네임으로 입장하면 그 사람의 연결이 끊겼다. 이제 서버는 한글·영문·숫자 1~10자가 아니거나 `gm`으로 시작하는 닉네임을 거부하고, 클라이언트는 닉네임을 정규식으로 해석하지 않으며, 강퇴는 대상 클라이언트에게만 `gmkicked` 명령으로 알린다.
- 투표 창에는 시간 제한이 없다. 그래서 20초 안에 투표하지 못한 사람이 라이어의 추리 시간에 표를 내서 전체 표 수가 접속자 수와 같아지면 추리 대기가 끊겼고, 라이어가 아직 답하지 않았으면 그대로 졌다. 이제 서버는 투표 시간에 들어온 표만 받는다.
- 서버를 만들 때 포트 검사 결과를 무시하던 조건문(`chk = true`)을 고쳤다. 포트를 열지 못하면 안내를 띄우고 로그인 화면으로 돌아간다. 전에는 동작하지 않는 서버 창만 남았다.
- JDK 17로 빌드와 테스트를 돌리는 GitHub Actions를 추가했다.

## 배운 점 / 한계

- **TCP 소켓과 멀티스레드 직접 경험**: 스레드 생성·동기화·자원 정리를 프레임워크 없이 직접 다뤘다. 동시 접속 환경에서 강퇴·브로드캐스트 타이밍 버그를 디버깅한 것이 가장 기억에 남는다.
- **알게 된 한계**:
  - 텍스트 접두사 기반 프로토콜은 확장에 취약하다. 다시 만든다면 JSON 같은 구조화된 메시지와 명령 enum을 쓰겠다.
  - 동기화를 `Vector`에 기대고 있어, 게임 진행 중 입퇴장이 겹치면 순회와 수정이 경합할 수 있다.
  - 네트워크 스레드에서 Swing 컴포넌트를 직접 갱신한다. `SwingUtilities.invokeLater`로 EDT에 위임했어야 한다.
  - 리소스를 작업 디렉터리 상대 경로로 읽어 JAR로 패키징하면 깨진다. classpath 리소스로 옮겨야 한다.
  - 서버는 투표 시간 밖의 표는 버리지만, 표를 보낸 사람이 이미 투표했는지와 제시어 추리를 보낸 사람이 라이어인지는 확인하지 않는다. 수정된 클라이언트는 여러 번 투표하거나 라이어 대신 추리를 보낼 수 있다.
